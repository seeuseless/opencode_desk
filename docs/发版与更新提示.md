# 发版与更新提示

给用户装好的青鸟发一个新版本时，走「改版本号 → 打 tag → CI 出包」三步。
用户那边的「设置 → 关于」会自动看到更新提示，点两下就完成升级。

## 一、发版（维护者）

> ### ⚠️ 前置条件：仓库必须是公开（public）的
>
> 应用**不携带、也不该携带 GitHub 凭据**，它对 GitHub 是匿名请求。而匿名访问非公开仓库时
> GitHub 一律返回 **404**（不是 403）——所以仓库只要是 private，检查更新就永远失败，
> 且提示会写成「读不到发布信息：仓库未公开（或地址不对），也可能还没建过任何 Release」。
>
> **实测**（2026-09）：本仓库 `seeuseless/opencode_desk` 当前匿名访问返回 404，
> 而 `git ls-remote`（带本机保存的凭据）能正常列出 `master` / `v0` 两个分支 ——
> 说明它是**私有仓库**。发版前请先到
> <https://github.com/seeuseless/opencode_desk/settings> 底部把可见性改成 Public，
> 否则用户端「设置 → 关于」永远只能看到检查失败。
>
> 另一条实测记录：GitHub 对**未登录**的 API 请求按出口 IP 限流（共享网络下常见），
> 撞上时提示「GitHub 接口限流，稍后再试即可」。这不是代码问题，过一会儿就好。

```bash
# 1. 改版本号（唯一事实来源）
#    package.json 的 version 与即将打的 tag 必须对得上：
#    应用内「当前版本」读的就是安装包里的这个值，对不上会让用户一直看到"有新版本"。
vim package.json            # "version": "0.0.2"

# 2. 提交推送
git add -A && git commit -m "release: v0.0.2" && git push

# 3. 打 tag 并推送 —— 这一步触发 CI
git tag -a v0.0.2 -m "release v0.0.2"
git push origin v0.0.2
```

`.github/workflows/release.yml` 会在 `windows-latest` 上：
`yarn install --frozen-lockfile` → `yarn dist`（含 `electron-vite build` 与
`electron-builder --win`）→ 把 `dist/青鸟-Setup.exe`、`dist/latest.yml` 上传到
`v0.0.2` 这个 Release。

跑完去 <https://github.com/seeuseless/opencode_desk/releases> 确认附件里有
**`青鸟-Setup.exe`**（名字必须完全一致，见下节）。想给用户写点更新说明，直接在
Release 页面编辑那一版的描述即可——应用里「发现新版本」区块显示的就是这段正文。

> 也可以在 Actions 页面手动触发（`workflow_dispatch`）补跑某个 tag：填 `v0.0.2` 即可。

## 二、用户端是什么体验

「设置 → 关于」一页搞定，全流程不需要用户去浏览器翻 Release：

| 步骤 | 界面 | 背后做了什么 |
| --- | --- | --- |
| 1 | 点「检查更新」 | 问 GitHub Releases 最新版，本地比对版本号（`updater.ts` 的 `isNewer`，非简单字符串比较） |
| 2 | 看到新版本号与更新说明 | 显示 Release 的 tag、正文、发布时间；「查看发布页」可去浏览器看完整内容 |
| 3 | 点「下载更新」 | 流式下载到 `~/.qingniaoai/updates/`，进度条实时走；可随时「取消下载」 |
| 4 | 点「立即安装并重启」 | 拉起 `青鸟-Setup.exe`，**本应用随即退出**（安装器要求文件不被占用）；NSIS 装完会自动重新启动青鸟 |

macOS 那边 dmg 只能"挂载磁盘映像"，替不了你完成替换，所以第 4 步会改成
提示用户手动把青鸟拖进「应用程序」。

## 三、两个必须守住的约定

### 1. 安装包文件名固定，不带版本号

`electron-builder.yml` 里写死了：

```yaml
artifactName: ${productName}-Setup.${ext}   # → 青鸟-Setup.exe
```

因为应用内的"一键下载"用的是**固定地址**：

```
https://github.com/seeuseless/opencode_desk/releases/latest/download/青鸟-Setup.exe
```

这条路不经过 `api.github.com`（国内常被阻断），`releases/latest/download/<固定名>`
是能直连的下载通道——代价就是**每次发版覆盖上传同名附件**。历史版本靠 git tag
与各自的 Release 页面追溯。

### 2. 版本号 = tag = package.json

| 位置 | 作用 |
| --- | --- |
| `package.json` 的 `version` | 打包进安装包，应用内显示为「当前版本」 |
| git tag（如 `v0.0.2`） | CI 触发条件；`updater.ts` 摘掉 `v` 前缀后与当前版本比较 |

两段式/三段式都支持（`v0.1`、`v0.0.2` 均可）。

## 四、检查更新失败怎么办

`updater.ts` **不编造版本号**：查不到就显示失败原因，并给一个「打开发布页」的出口。
常见原因与处理：

| 提示 | 原因 | 处理 |
| --- | --- | --- |
| `读不到发布信息：仓库未公开（或地址不对），也可能还没建过任何 Release` | 仓库是 private（匿名请求一律 404）；或仓库名写错；或只打了 tag 但没在 GitHub 上建 Release | 把仓库改成 Public / 检查 `resources/update.json` 里的 `repo` / 在 tag 上建 Release |
| `GitHub 接口限流（HTTP 403）` | 未登录的 API 限额按出口 IP 算，共享网络容易撞上 | 稍后重试；或点「打开发布页」自行下载 |
| 请求超时 / `fetch failed` | 网络不通（`api.github.com` 在国内常被阻断） | 点「打开发布页」自行下载；或配代理后重试 |
| `下载不完整（x / y 字节）` | 下载中途断流 | 重下（半截文件已自动删掉，不会留下坏包） |

> 检查更新只读 GitHub 公开接口，**不需要登录、不上报任何用户数据**。

## 五、相关代码位置

| 文件 | 职责 |
| --- | --- |
| `electron/main/updater.ts` | 查最新版、版本比较、流式下载 + 进度、拉起安装包 |
| `electron/main/index.ts` | `update:*` 六个 IPC 通道；状态变化推给界面 |
| `electron/preload/index.ts` | 渲染层桥（`getUpdateState` / `checkUpdate` / `downloadUpdate` / `cancelUpdate` / `installUpdate` / `openRelease` / `onUpdateChanged`） |
| `src/renderer/components/UpdatePanel.tsx` | 设置 → 关于 界面 |
| `scripts/gen-update-meta.mjs` | 生成 `resources/update.json`（仓库坐标、tag 前缀；换仓库只改它） |
| `.github/workflows/release.yml` | tag → 构建 → 上传附件 |

> 之所以没有用 `electron-updater`：它默认要吃 electron-builder 生成的 `latest.yml`，
> 那份文件的大小/校验值必须与实际产物逐字节一致，手工维护极易失真。GitHub Releases
> 自带的 `tag_name` / `body` / `assets` 已经够用，少一份要维护的元数据。
