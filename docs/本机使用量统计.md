# 本机使用量统计

> 以代码为准，改动后同步。

## 现状（2026-09-25 实现完成）

设置 → 使用量 已改为**纯本地数据源**，不需要平台、不需要登录，整页常驻显示（已从 `REMOTE_TABS` 摘出）。

## 数据链路

1. 内核自身在会话存储里记录每条 assistant 消息的 `tokens`（total/input/output/reasoning/cache）、
   `cost`、`modelID`、`time`。存储在 `~/.qingniaoai/data/opencode/opencode.db`（新版 SQLite），
   `message` 表 `data` 列是 JSON。
2. 主进程 `electron/main/usage.ts` 聚合：
   - `GET /session` **不带 directory** 即返回全部项目会话（含 `time.updated`）——不用维护项目清单；
   - `GET /session/{id}/message` 拉消息摘用量事实；
   - 会话级缓存：`time.updated` 没变的会话直接复用上次结果，只重扫变化的会话；
   - 一批 6 个并发，单会话失败跳过不炸整体；
   - 聚合出 all/today/yesterday（固定口径）+ range/models/series（随区间，默认近 30 天）；
   - 日期按消息创建时刻的本地时区（`ymdLocal`）。
3. IPC：`usage:local`（index.ts）→ preload `usageLocal(range)` → 渲染层 `window.qingniao.usageLocal`。
   类型 `LocalUsage*` 在 `electron/main/types.ts`，经 `oc.ts` re-export。

## 验证过的关键事实

- `/session` 无参返回跨项目全集（实测 17 会话），session 对象自带 `directory/cost/tokens`。
- assistant 消息 `tokens.total = input + output + reasoning + cache.read(+write)`。
- 内核没有 usage 汇总 REST 端点（扫过二进制确认）；插件 hook（event/message.updated）可行但只能记增量，
  被否——REST 聚合历史天然完整。

## 改动后要注意

- UsagePanel 已无 props（不消费登录态）；AccountPanel 仍是平台数据（账号页在 REMOTE_TABS 里）。
- 本机统计没有积分概念；积分只在平台侧（账号页）。
- 改聚合口径/字段时同步 `docs/` 与 `UsagePanel` 的说明文案。
