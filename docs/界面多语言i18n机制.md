# 界面多语言（i18n）机制

> 以代码为准，改动后同步。

## 现状

- 语言：`简体中文 zh`（默认）/ `繁體中文 tw` / `English en`，选项在 设置 → 通用 → 语言。
- 实现在 `src/renderer/i18n.ts`，渲染层唯一入口，主进程原生菜单不参与（mac 菜单本就是英文）。
- 本地持久化键：`qingniao.lang`（localStorage，走 `store.ts` 的 load/save）。

## 设计约定

1. **简体中文文案就是字典键**：`t('保存')` 在 zh 下原样返回；tw/en 查表，缺键回退简体原文。
   所以漏翻不报错，但校验脚本可保证不漏（见下）。
2. **语言状态由 App 持有，切换必须先拨模块变量再 setState**：`App.tsx` 的 `changeLang` 先
   `setLang(l)`（更新 i18n 模块变量 + 存档）再 `setLangState(l)` 触发重渲染。顺序不能反——
   `t()` 在**渲染期**读模块变量，若只 setState（把模块变量更新放 effect 里），重渲染那一帧
   整树仍按旧语言渲染，表现为「点语言没反应、再点别处才变」。effect 只负责 `<html lang>`。
3. **插值用 `{x}` 占位**：`t('已获取 {n} 个模型', { n })`；不传 params 时不做替换，
   因此键里含 `{video_id}` 这类字面占位符是安全的。
4. **只翻界面文案，不翻内核协议文本**：记忆注入（`MEMORY_PREFIX` 及 ChatView 组装的 memText）、
   浏览器上下文（`BROWSER_CTX_PREFIX`…）、附件路由 prompt、`SCHEDULE_PREFIX = '[计划] '`
   都是发给内核/写入磁盘的数据标记，保持简体原样。
5. **模块级常量表（label/tip/name/desc）存简体原值，在渲染处包 `t()`**：
   如 SettingsView 的 `TABS`/`MODALITY_LABELS`/`GEN_LABELS`、theme.ts 的主题名、codeStyle.ts 的
   `desc`、oc.ts 的 `MODEL_ROLE_LABEL`、ChatView 的 `TOOL_META`/`PERM_LABEL`、license.ts 条款正文、
   SchedulesView 的 `WEEK`。license/条款在 UpdatePanel 渲染处逐条 `t()`。

## 新增界面文案的操作

1. 界面里直接写 `t('简体文案')`（含参数用 `{x}` 占位）。
2. 在 `i18n.ts` 对应分组（TW_*/EN_* 按文件分段）补两条翻译。
3. 回归：`npm run typecheck:web`（TypeScript），构建 `npm run build`。

## 已知触点清单

- 语言切换 UI：`SettingsView.tsx` 通用区（`LANGS` 来自 i18n.ts，label 固定各语言原文不翻译）。
- Props 链：`App.tsx` → `SettingsView` 传 `lang`/`onLang`。
- 数字单位：`format.ts` `fmtTokens` —— en 用 `Intl.NumberFormat('en', { notation: 'compact' })`，
  tw 用 萬/億，zh 用 万/亿；`fmtNumber` 千分位各语言通用。
- 变量遮蔽陷阱：源码里多处回调参数/局部变量名叫 `t`（`tasks.map((t…)`、`const t = PROVIDER_…`、
  lezer `tags as t`）会遮蔽翻译函数 `t`，改名才接入过：ThinkingPicker `op`、SchedulesView `tk/task/ts`、
  SettingsView `tb/th/tk/preset`、CodeWorkspace lezer 改 `tg`、UsagePanel load `(f, td)`、
  ChatView `ttl/qt/tm/out`。**新代码里别再用 `t` 做变量名。**
- 遮蔽排查脚本思路：按行匹配「引号内含中文但行内无 `t(`」可快速找漏网文案（本次任务用后已删）。
